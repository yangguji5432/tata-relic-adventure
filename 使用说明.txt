遗迹探险助手 · ADB后台版

这个版本通过 ADB 获取安卓截图、发送安卓点击和滑动，不需要占用 Windows 焦点、鼠标或模拟器键盘映射。可以一边运行一边使用其他 Windows 窗口。
游戏必须保持在安卓内部前台。切换安卓应用、断开设备会停止操作。模拟器必须继续运行；最小化后是否继续渲染取决于模拟器设置，首次请自行确认。电脑休眠后不能继续运行。

一、运行条件
1. Windows，已安装 Python 3.10 或更高版本，并带有 tkinter。
2. 安装 Pillow：在此文件夹打开终端，运行 python -m pip install -r requirements.txt。
3. Windows 必须具备简体中文 OCR。缺少时，可在 Windows 语言设置中安装中文相关语言功能。
4. 已安装并运行 MuMu，启用本机 ADB 连接。软件会尝试查找 MuMu 的 adb.exe，也可以手动选择现有 adb.exe。此目录不附带模拟器或 ADB。
5. 双击“启动后台版.bat”。这是一份 Python 源码版，并非免安装 exe。

二、第一次连接
1. 在模拟器内打开游戏的“遗迹探险”主页。
2. 点击“刷新设备”，选择正确的实例。多个地址可能对应同一个模拟器。
3. 如果没有设备，确认模拟器的 ADB 设置，在端口框填写其实际本机地址，再点“连接此端口”。默认 127.0.0.1:16384 只是示例；本机实测也出现过 127.0.0.1:7555，不要认定地址固定。
4. 点击“绑定当前游戏”。软件保存这个设备对应的安卓应用和截图尺寸。
5. 点击“查看后台画面”，确认读到的是你要运行的游戏。
6. 如果截图包含安卓导航栏、黑边或其他区域，点击“校准游戏区域”，拖框选择完整游戏画面，保留游戏底部按钮。不要包含安卓导航栏。ADB 截图本身不含 Windows 标题栏和模拟器侧栏。

三、校准点击位置
软件提供默认位置，但不同画面布局可能需要校准。这里使用安卓触摸，不再依赖空格、A、D、C 的模拟器按键绑定。
点击“校准点击位置”，在下拉框选择一个动作，再在截图中单击该动作对应的按钮位置，最后“保存校准”。校准中的单击只记录位置，不会操作游戏。
各动作分别保存：开始探险、准备前进、宝藏展示继续、增益收下、结算收下、撤离、战斗、打开图鉴、未知画面尝试继续。
建议在对应游戏界面分别校准，尤其检查开始、前进、撤离、战斗、结算和图鉴。奖励弹窗可选其允许点击继续的位置。
“未知画面尝试继续”是一个通用触摸点，不能保证等同于原先的空格映射，请选择你认为适合继续的位置。
调整 Windows 中模拟器窗口的大小通常无需重校准；修改安卓内部的分辨率后，需要重新绑定并校准区域和点击位置。更换游戏区域会清除旧点击校准。

四、图鉴
首次所有20件宝藏的分数都为0，包括“图坦卡门金面”。不会附带其他人的个人分数。
可以手动填写“名称=分数”，再点“保存图鉴”。编辑区被误删时，点“恢复图鉴”，核对后保存。
也可以通过“导入图鉴”选择旧版本 data/catalog.json，核对编辑区后保存。不要导入旧版本的 settings.json。
扫描步骤：在游戏主页点“打开游戏图鉴”，确认游戏图鉴位于最顶部，再点“扫描图鉴”。软件读取顶部、向下滑动一次、等待2秒回正，再读取底部。完成后核对编辑区并“保存图鉴”。
扫描时，经过重复识别确认的分数可以覆盖已有更低或更高的分数，用于纠正多识别一位数字的情况。无法确认的内容请手工核对。
图鉴按分数从高到低排列；未识别的空位以？？？=0置于末尾。未解锁物品不会固定占据某个行列，不能只凭格子顺序判断名称。
自动探险中，同一宝藏名称与分数连续识别一致，而且高于现有分数时，会自动保存并刷新编辑区；较低或相同分数不会在此流程覆盖记录。
注意：获得宝藏时就更新记录，不会等到最终撤离后再更新，也不会在之后战败时回滚。

五、开始探险
1. 先保存核对后的图鉴。
2. 默认普通撤离阈值为20%，保护纪录阈值为60%。胜率小于或等于对应阈值时撤离；例如80%+5%按85%计算。阈值可以修改。
3. 每次打开软件默认勾选“仅观察，不点击”。先启动观察，检查日志中的主页、前进、遇敌、奖励、结算等识别结果；停止后取消该勾选，再启动自动操作。
4. “结算后继续下一局”默认关闭，按需勾选。
5. 点击“启动（3秒后）”。之后可以切换 Windows 窗口；无需让模拟器获取焦点。
6. 点击“停止 F9”或按 F9 请求停止。已发出的单次安卓点击无法撤回。

识别以约每1秒发起下一轮为目标，不再固定等待5秒。ADB截图和Windows OCR本身也耗时，因此实际间隔可能超过1秒；当前机器实测完整截图及识别约4秒，不能保证每秒完成一次。
软件需要连续稳定识别后才执行下一步。画面未知时，前20秒每隔至少1秒在“未知画面尝试继续”的校准位置点击一次；之后每隔至少5秒尝试一次，持续未知满60秒暂停，60秒是从首次未知开始计算的总时长。实际间隔还受截图、识别和ADB耗时影响，不会并发补点。仅观察模式不会点击；重新确认画面后结束本轮重试。
已认出遇敌但读不清胜率时，会继续重试，仍无法确认则暂停，不会盲目战斗。
本局获得高于图鉴的宝藏后，保护模式会保持到本局结束；所以后续获得较低分宝藏时日志仍可能显示保护模式=True。中途接管已进行的探险或无法确认状态时也采用保护阈值。

六、常见问题
MuMu 多画面：助手动态解析游戏所在逻辑画面和活动物理显示器映射。截图使用物理ID，点击/滑动使用逻辑编号，不固定使用0或2。绑定日志会显示实际编号和截图尺寸。
更新多画面修复后：关闭旧助手，更新代码并保留 data 中的个人图鉴，重新启动、绑定游戏、查看后台画面，再核对校准。不要删除个人图鉴。尺寸变化时重新校准。
提示目标画面不唯一或没有活动映射：关闭多余游戏画面、确认游戏在安卓内部前台后重试。程序不会回退到默认桌面操作。运行中映射变化也会暂停，需要重新绑定检查。
ADB截图格式异常：已兼容PNG前的短文本警告，并继续校验图片。仍失败时，日志会显示返回字节数及开头内容，可据此排查，而不是反复点连接。
没有设备：确认 ADB 路径和模拟器本机端口，重新刷新；不要直接照抄他人的端口。
绑定后提示安卓应用变化：返回绑定的游戏再启动，或者在正确游戏中重新绑定。
识别正确却点不到按钮：校准对应动作的点击位置。修改键盘映射不会改变 ADB 点击位置。
识别经常未知：先查看后台截图是否完整、方向是否正确、是否有黑边或安卓导航栏，再校准游戏区域。游戏动画、遮挡或画面改版也可能导致识别失败。
扫描错字/数字：在编辑区手动修正后保存；OCR 无法保证每次完全准确。
暂停响应有延迟：正在进行的 OCR 可能需要先返回，等待其结束；ADB 子进程支持停止请求，不会主动关闭模拟器或停止整个ADB服务。

七、数据与分发
本版本的数据在本目录的 data 子文件夹，与前台版分开。catalog.json 是个人图鉴，settings.json 包含设备、绑定和校准等设置。
给别人使用时建议发送附带的干净压缩包。不要附带你的 data、个人截图或日志；对方应绑定自己的设备并校准。
不要同时运行前台版和后台版自动操作同一个游戏。
