# 塔塔冒险队 · 遗迹探险助手

通过 **ADB 截图、安卓触摸和画面识别**，辅助进行遗迹探险。运行时无需让 MuMu 获得 Windows 焦点，可以同时使用其他 Windows 窗口。

目前是可试用的 Python 源码版，适用于 Windows + MuMu。已验证后台截图与准备前进画面的识别；完整一局的实际点击流程仍需试用核对。首次请保留“仅观察”，确认状态和点击位置后再开启自动操作。

## 功能

- 识别探险主页、准备前进、遇敌、宝藏/增益和结算画面。
- 根据胜率选择撤离或战斗，支持将 `80% + 5%` 计算为 `85%`。
- 普通撤离阈值默认 **≤20%**；获得新纪录后的保护阈值默认 **≤60%**，均可修改。
- 管理全部20件宝藏，初始分数均为0；获得更高分宝藏并重复确认后自动更新。
- 图鉴只扫描顶部与底部两页：滑动后等待2秒回正，再读取第二页；扫描确认的低分也能覆盖旧值，用于修正 OCR 多识别数字的情况。
- 支持设备选择、游戏绑定、游戏区域和各动作点击位置校准。
- 未知画面每隔至少5秒尝试点击继续，持续1分钟仍未知则暂停；支持 F9 停止。

## 安装与启动

需要 Windows、Python 3.10+（含 tkinter）、Pillow、简体中文 Windows OCR，以及已经安装的 MuMu 和 `adb.exe`。

下载本仓库并解压，在项目目录运行：

```powershell
python -m pip install -r requirements.txt
python app.py
```

也可以在安装依赖后双击 **启动后台版.bat**。仓库不附带 Python、模拟器或 ADB，也没有预编译 exe。

## 首次使用

1. 在模拟器内打开游戏的“遗迹探险”主页。
2. 启动助手，确认 ADB 路径，点击“刷新设备”并选择实例。找不到设备时，填写模拟器实际的本机 ADB 地址，再“连接此端口”；默认端口只是示例。
3. 点击“绑定当前游戏”，再“查看后台画面”，确认设备和游戏正确。
4. 如果画面含黑边或安卓导航栏，通过“校准游戏区域”选中完整游戏画面。
5. 在“校准点击位置”中，分别核对开始、前进、宝藏继续、增益收下、结算、撤离、战斗、图鉴和未知画面继续的位置。单击校准截图只记录坐标，不会操作游戏。
6. 填写图鉴并“保存图鉴”，或打开游戏图鉴、滚到顶部后扫描，核对扫描结果再保存。支持导入旧版 `data/catalog.json`。
7. 保留“仅观察，不点击”启动一次，检查日志。停止后取消该勾选，按需选择“结算后继续下一局”，再启动自动操作。

更完整的连接、校准、扫描和排错步骤见 [使用说明](使用说明.txt)。

## 运行规则与限制

| 项目 | 行为 |
| --- | --- |
| Windows 焦点 | 无需保持模拟器焦点，不依赖空格/A/D/C映射 |
| 安卓应用 | 游戏必须位于安卓内部前台，切到其他应用会暂停 |
| 识别频率 | 目标约每1秒进入下一轮；ADB 与 OCR 耗时会使实际间隔更长，实测约4秒，不保证1Hz |
| 保护模式 | 本局触发后保持到结算；后续拿到较低分物品不会解除。中途接管或状态不明时也会保守保护 |
| 自动更新图鉴 | 获得宝藏时确认更高分即保存；之后战败不会回滚此记录 |
| 扫描图鉴 | 重复识别确认的分数可以覆盖较低或较高的旧值；保存前请核对 |
| 胜率读不清 | 重试后暂停，不盲目战斗 |
| 分辨率变化 | Windows 窗口缩放通常无需重校准；安卓内部截图尺寸改变后要重新绑定和校准 |

模拟器必须持续运行。最小化后是否继续渲染取决于模拟器设置，需要自行确认。电脑休眠后无法继续运行。画面改版、动画和 OCR 误识别仍可能造成暂停或错误操作，首次请在旁检查。

“未知画面尝试继续”使用可校准的通用触摸点，不能保证等同于原先的空格按键映射。

## 数据与项目结构

```text
app.py             桌面界面、连接与校准
adb_backend.py     ADB截图、点击、滑动和应用检查
engine.py          状态识别、探险流程和图鉴逻辑
visual.py          图像锚点匹配
ocr.ps1            Windows OCR
assets/            识别用的局部游戏画面样本
data/              首次运行后生成的个人图鉴、设备绑定与设置
```

`data/`、缓存、个人截图和日志不应上传。分享时对方需要选择自己的设备并重新校准。不要同时用前台版和后台版控制同一个游戏。
