# 塔塔冒险队活动助手

同一窗口提供 **遗迹探险**、**围猎萨满（半自动建议）** 和 **钓鱼助手** 三个活动页。三项活动共用ADB连接、游戏绑定和校准，均通过安卓截图和触摸运行。一次只运行一个任务。原遗迹探险规则保留：保护模式只在确认更高分并成功刷新图鉴后开启。

启动：安装 `requirements.txt` 后双击 **启动活动助手.bat**。识别依赖 NumPy、OpenCV headless 和 Pillow。只需安装最外层 requirements.txt。详见 [合并版使用说明](合并版使用说明.txt)；下文原有详细规则主要对应遗迹探险。

## 自选萨满提示音

围猎页点击“选择提示音文件”，选择本机WAV、MP3、WMA等音频，再点“试听警报”。文件路径保存在本机设置中，不复制进分享包；移动或删除文件后需要重新选择。可点“恢复默认声音”回到80毫秒短哔声。

WAV使用Windows异步播放，其他格式通过Windows本机媒体组件播放，具体支持取决于系统；无法播放时日志会提示换用PCM WAV。建议使用开头没有静音的短WAV，文件自身的静音和ADB识别耗时仍可能造成延迟。

## 钓鱼助手 · ADB后台版

本活动**参考并复用了 [zz11-m/tt_fish](https://github.com/zz11-m/tt_fish) 的识别与黄条相位预测源码**。保留原作者 zz11-m and contributors、GPL-3.0-only许可证及源码快照提交 c1263f7e84b77e47974f76ed733772dc6c6c0646。实时截图和输入由本项目的 fishing_adb.py、adb_backend.py 接管，不再加载原版前台窗口界面。

1. 使用上方ADB选择实例，绑定当前游戏，查看后台画面并框选完整竖屏游戏区域，保留游戏内部底部栏。
2. 打开“钓鱼助手”标签，校准“钓鱼：下钩/拉钩/黄条/收下”共用触摸点，位置需覆盖圆形操作按钮下半部和结算收下按钮。
3. 默认持续仅观察，点击“启动钓鱼（3秒后）”检查准备下钩、等待上钩、拉钩、黄条与结算阶段。确认后停止，再取消仅观察启动。
4. 支持不停钓、次数/时间上限、自动黄条开关及输入延迟补偿（0—250毫秒）。F9停止。无需空格映射、Windows焦点或可见窗口；安卓内部仍需保持游戏前台。

ADB截图指定游戏所在物理画面，触摸指定逻辑画面。黄条计划在发送前、目标检查之后重新校验，过期或未到时机则跳过，等待新截图。黄条命中率仍受ADB速度和延迟波动影响；自动判定为试用，尚未实机验证完整钓鱼流程，可以关闭自动黄条手动操作。

所有活动使用同一个任务通道，不能同时运行。钓鱼不发送Windows空格或其他键盘输入。third_party/tt_fish/README.md 保留的是上游前台版说明，本整合版使用方式以本文件为准。原版源码/测试保留，上游独立自检所需MSS见其内层requirements；运行本后台助手只需最外层依赖。

## 围猎萨满：建议半自动使用

当前萨满出现提醒相对可用，但死亡、位置与退出识别误判较多。建议用户在旁判断萨满是否死亡、是否已经转打小怪，并手动退出。

**推荐：仅声音提醒。** 勾选“仅观察：持续测试萨满出现与死亡线索”和“萨满出现时声音提醒”，启动后手动进入200倍场。助手持续提示头像及识别线索，不点击、不使用技能；锁定和退出由用户完成。普通“仅观察，不点击”只读一次，不能代替持续观察。

**可选：自动锁定加声音提醒。** 取消两种观察模式，开启声音提醒，启动后程序按现有流程尝试自动锁定，用户在旁判断并及时手动退出。现有自动退出、超时与下一轮规则仍会运行；这不是“只自动锁定、其余完全交由用户”的独立模式。可关闭“自动进行下一轮”避免离场后自动重进。

**提示：萨满可能在画面外或入场前被秒杀，程序随后仍可能释放锁定，转打小怪；识别失效时不保证及时退出或暂停，会继续消耗金币。F9只停止助手，不能停止游戏已开启的自动攻击，需要手动退出场地。** 不建议无人看管使用。

声音改为直接调用Windows Beep播放80毫秒短哔声，不加载音频文件，首帧匹配头像便异步播放，重复头像不连续响；自动锁定仍按原来的连续确认规则处理。声音可能先于自动锁定，仍受ADB截图、图像识别和Windows音量设置影响。“试听警报”使用同一个声音。

本次只调整围猎介绍、使用建议、风险提示和声音提醒链路；游戏识别、锁定、退出及下一轮决策规则保留。其他开关与校准方式见“合并版使用说明.txt”。

## 遗迹探险

通过 **ADB 截图、安卓触摸和画面识别**，辅助进行遗迹探险。运行时无需让 MuMu 获得 Windows 焦点，可以同时使用其他 Windows 窗口。

目前是可试用的 Python 源码版，适用于 Windows + MuMu。已验证后台截图与准备前进画面的识别；完整一局的实际点击流程仍需试用核对。首次请保留“仅观察”，确认状态和点击位置后再开启自动操作。

## 功能

- 识别探险主页、准备前进、遇敌、宝藏/增益和结算画面。
- 根据胜率选择撤离或战斗，支持将 `80% + 5%` 计算为 `85%`。
- 普通撤离阈值默认 **≤20%**；获得新纪录后的保护阈值默认 **≤60%**，均可修改。
- 管理全部20件宝藏，初始分数均为0；获得更高分宝藏并重复确认后自动更新。
- 图鉴只扫描顶部与底部两页：滑动后等待2秒回正，再读取第二页；扫描确认的低分也能覆盖旧值，用于修正 OCR 多识别数字的情况。
- 支持设备选择、游戏绑定、游戏区域和各动作点击位置校准。
- 未知画面前20秒每隔至少1秒尝试点击继续，之后每隔至少5秒尝试一次；持续未知满60秒暂停，支持 F9 停止。实际间隔还受截图、识别及ADB耗时影响。

## 安装与启动

需要 Windows、Python 3.10+（含 tkinter）、Pillow、简体中文 Windows OCR，以及已经安装的 MuMu 和 `adb.exe`。

下载本仓库并解压，在项目目录运行：

```powershell
python -m pip install -r requirements.txt
python app.py
```

也可以在安装依赖后双击 **启动后台版.bat**。仓库不附带 Python、模拟器或 ADB，也没有预编译 exe。

## 首次使用

1. 在模拟器内打开游戏的“遗迹探险”主页。
2. 启动助手，确认 ADB 路径，点击“刷新设备”并选择实例。找不到设备时，填写模拟器实际的本机 ADB 地址，再“连接此端口”；默认端口只是示例。
3. 点击“绑定当前游戏”，再“查看后台画面”，确认设备和游戏正确。
4. 如果画面含黑边或安卓导航栏，通过“校准游戏区域”选中完整游戏画面。
5. 在“校准点击位置”中，分别核对开始、前进、宝藏继续、增益收下、结算、撤离、战斗、图鉴和未知画面继续的位置。单击校准截图只记录坐标，不会操作游戏。
6. 填写图鉴并“保存图鉴”，或打开游戏图鉴、滚到顶部后扫描，核对扫描结果再保存。支持导入旧版 `data/catalog.json`。
7. 保留“仅观察，不点击”启动一次，检查日志。停止后取消该勾选，按需选择“结算后继续下一局”，再启动自动操作。

更完整的连接、校准、扫描和排错步骤见 [使用说明](使用说明.txt)。

### MuMu 多显示画面修复与升级

部分 MuMu 实例的桌面和游戏位于不同逻辑画面，默认截图可能读到桌面。现在会从各画面的前台活动识别游戏，优先匹配已绑定的包名，再通过活动 `DisplayViewport` 动态匹配物理显示器 ID。截图指定物理 ID，触摸指定逻辑编号；不会固定使用0或2，也不会在解析失败时回退到默认桌面。

兼容 PNG 前的短文本警告，去除后仍校验和解码 PNG。没有唯一活动映射、同一游戏出现在多个画面，或运行中画面映射变化时，会暂停并提示。绑定日志显示逻辑编号、物理 ID 和截图尺寸，便于排错。

升级时关闭旧助手，更新代码，保留原 `data/` 中的图鉴；重新启动后选择设备、绑定游戏并预览，确认是游戏画面，再核对区域和触摸校准。图鉴不需要清零。如果截图尺寸变化，重新校准。

多显示修复通过12项合成样本/模拟ADB的回归测试；尚未在用户的另一台电脑上验证本次实现。运行测试：`python -m unittest discover -s tests -v`。更新内容见 [CHANGELOG.md](CHANGELOG.md)。

## 运行规则与限制

| 项目 | 行为 |
| --- | --- |
| Windows 焦点 | 无需保持模拟器焦点，不依赖空格/A/D/C映射 |
| 安卓应用 | 游戏必须位于安卓内部前台，切到其他应用会暂停 |
| 识别频率 | 目标约每1秒进入下一轮；ADB 与 OCR 耗时会使实际间隔更长，实测约4秒，不保证1Hz |
| 保护模式 | 只有宝藏名称与分数连续识别一致、确认高于旧记录且成功保存图鉴更新后才开启。本局触发后保持到结算；未知画面、未读清、中途接管或不一致读数不会触发 |
| 自动更新图鉴 | 获得宝藏时确认更高分即保存；之后战败不会回滚此记录 |
| 扫描图鉴 | 重复识别确认的分数可以覆盖较低或较高的旧值；保存前请核对 |
| 胜率读不清 | 重试后暂停，不盲目战斗 |
| 分辨率变化 | Windows 窗口缩放通常无需重校准；安卓内部截图尺寸改变后要重新绑定和校准 |

模拟器必须持续运行。最小化后是否继续渲染取决于模拟器设置，需要自行确认。电脑休眠后无法继续运行。画面改版、动画和 OCR 误识别仍可能造成暂停或错误操作，首次请在旁检查。

“未知画面尝试继续”使用可校准的通用触摸点，不能保证等同于原先的空格按键映射。

## 数据与项目结构

```text
app.py             桌面界面、连接与校准
adb_backend.py     ADB截图、点击、滑动和应用检查
engine.py          状态识别、探险流程和图鉴逻辑
visual.py          图像锚点匹配
ocr.ps1            Windows OCR
assets/            识别用的局部游戏画面样本
data/              首次运行后生成的个人图鉴、设备绑定与设置
```

`data/`、缓存、个人截图和日志不应上传。分享时对方需要选择自己的设备并重新校准。不要同时用前台版和后台版控制同一个游戏。
